# 从专家判断学习谱面组织

这个框架从真实谱面建立可反复修正的判读经验。当前专家判断约束各自的源码、范围与风格表达；自然谱面提供重复、发展与变体；community tags 提供整张 difficulty 的人类语境。学习的产物是对组织关系的解释，以及知道解释在哪里失效。原来的标签体系、专家判断和谱面不随解释一起改写。

操作入口见 [beatmap learning](beatmap-learning.md)。下面的具体关系来自 2026-09-07 至 09-08 对当前 139 条专家判断的源码研究，不是新的充分判据或阈值。

当前工作区保留了[本轮研究报告](../.local/expert-study-20260907/report.md)、[139 条逐例索引](../.local/expert-study-20260907/case-index.md)及[经验与修订索引](../.local/expert-study-20260907/memory-index.md)。这些本地学习产物保留精确来源，之后的 agent 可以从原例与经验版本继续研究。

## 同时读三个视角

| 视角 | 要形成的理解 | 可以用来反问自己的问题 |
| --- | --- | --- |
| 时间 | 毫秒与拍内位置、攻击分组、延续、留白、重启；音乐能量变化与按键变化各有范围 | 相同的细分变化是在延续一条路径、强调一个落点，还是改变了动作之间的连接？ |
| 动作 | 哪些手指进入、保留、退出、重新加入；哪些事件被组织成一个击组，哪些保持另有角色 | 相邻起音相同，尾点变化有没有改变下一步仍被占用的列？成组按放是否仍与另一保持角色并行？ |
| 组织 | 局部构件在重复 cell、乐句与更长发展中的功能；前景与背景；自然变体 | 一个 trill 是主体、收尾还是可截出的偶然片段？熟悉的 burst/jump/stream 在整个句子中怎样连接？ |

三个视角彼此修正。不要先用几何指标得出结论，再用“时序感”“手感”装饰理由。也无需每次填完一张固定表：沿着当前最有辨别力的关系继续观察。

动作解释允许讨论人类提供的 tap-like 经验；源码仍保留所有 LN 头尾。击组与单个 hit object 不是一一对应，也不意味着可以把两个原始时间戳合并。使用判定窗口容错的实际打法属于另外的执行假设，不能悄悄写进精确执行的 canonical profile。

## 用对照约束解释

只解释一个已知标签很容易。更有价值的是找到它也能解释的相反判断，随后修改关系、收窄范围，或留下真实未解问题。

| 想使用的简单解释 | 必须同时解释的人类案例 | 目前能保留的理解 |
| --- | --- | --- |
| 短 LN 或真实重叠足以决定 coordination | Who? 97595–98913 absent；Your Soulmate 1404510–1405260 supporting；End Time 21425–22592 prominent | 击组、保留到后续动作的角色、尾的先后与作用同时存在；没有统一时长分界 |
| 长锚下有短音就需要独立保持 | Materialize Anything 48104–48904 absent；finorza 12135–14268 supporting | 区别单长背景加短击，与另外仍在独立延续的长保持；检查完整角色关系 |
| 保持期间必须不断有新头 | Highscore 153281–153554 absent；Eviternity 50137–53977 supporting；Nibelungen 179933–182600 supporting | Highscore 有初始双头；后两例也允许整组起音后只有释放。完整分解与段落作用需比较，不能新增“没有新头必负”的规则 |
| 慢、稀疏、规则只能弱或不存在 | Go Beyond!! 32420–34820 absent；Overkill 32522–34937 prominent；A Fool Moon Night 167706–169445 prominent | 强度不是事件速率。保持场的分解、重新分配、背景/前景与整段表达需要分别说明 |
| 完整攻击行必须始终等于两个固定集合 | Tear Rain 112953–113968 prominent Trill；Senbonzakura 63932–65304 absent Trill | 持续核心可以与背景保持并行，但需检查每个额外事件的作用，不能靠删除中间行制造规律 |
| 多细分、方向变化、LN角色变化就是 Tech | Kanjou no Matenrou 389914–392610 absent；Pentiment 97007–98360 absent；OOPARTS 210998–212708 supporting | 描述变化如何作用于动作连接，单列变化清单不足。重复 cell 内部也可能已有表达 |
| 熟悉构件限制整个段落的强度 | Hysteric Night Girl 245000–255000 prominent；Arche 240000–250000 prominent；局部 Jack/Stream 负例 | 构件的功能与连接须回到被判断的完整范围；整段正例也不向所有子段传递标签 |

所有名称都应通过 human example ID、源码 SHA 和 scope 检索到原记录；表格本身不是完整证据。缺失人类评语时，对判定的解释仍由 agent 提出，不能使用原 agent rationale 冒充专家理由。

Kanjou / Search 的第二轮研究展示了如何真正修订：Kanjou 负例内部也有与 Search 正例对应的「半拍等待→三步 sixth-beat 短组→chord」，所以“停顿后的 burst 落点”必须撤回为分界解释。自然片段还提供了相同回折路径的规则版本。更窄的候选是 Search 中某种内部不等时序在不同列路径下反复保留；这描述了一个更具体的家族，仍未证明它就是人类分界。[逐事件对照与修订](../.local/expert-study-20260907/tech-b/iteration2-findings.md)保留了反例和未解部分。

## 如何使用自然变体

先指出当前解释预期保留的关系，再读真实变体，看哪里保持、哪里改变。可以沿同曲下一句、同 beatmapset 的其他 difficulty，或 community tag 引导的其他曲目探索。无需先给它们打 section 标签。

本轮的实际迁移包括：

- SYSTEM ERROR 的 EXTREME、EXTRA、HYPER 保留约 300 ms 的较大节奏，分别出现分批尾后 chord、齐尾 pair 后 chord、LN+tap 后两个 single 回答。难度差异包含动作组织变化。
- Tententengoku 的约 107 ms 骨架中，较晚加入的保持有时跨过背景尾，有时与其齐尾。一个组织家族可以有不同结束轮廓。
- BIKE 的短 LN 簇具有重复的起音分组和音频能量段，同时改变簇内尾长与尾序。应并行保留击组和释放轮廓，而非按“等长/不等长”直接决定手感。
- deathpiano 的自然后段更密，却出现更持续的 quarter-beat 流动。密度上升没有提供更强 Tech 的局部标签。
- Blue Zenith 的固定组交替允许有安排的长等待；Synthesis 的两个局部交替 cell 之间存在有作用的方向连接。不能把不等间距一概理解为组织中断，也不能删掉连接来制造更长的连续 trill。

重复出现帮助学习变体；同曲重复与已暴露专家判断都不能计作独立准确率。迁移没有解决的区别继续保留，例如 Kanjou 与 Search And Destroy、Symphony of the Night 与 Airborne Robots 的相近组织。

## 人类表达、源码与音频

判定、原评语、源码事实和解释是不同证据。人的简评可能描述主体或感知分组：Touhou Last Boss Rush 的“all LN”存在入口 tap；Who? 的近等长短 LN 有一条 78 ms 例外。保留两者，不为贴合文字删改源码，也不因一个字面例外否定专家判断。

真正不符需要明确记录。Machinegun 225000–235000 的 Tech absent 评论称 redline 导致间隔变化，但源码对应 reviewContext 223000–237000 没有 tempo change。当前保持该判断，同时将这条因果理由列为未解。不能用猜测的音频速度变化替换一个已被源码否定的 timing-point 事实。

Mel 提供同一时间轴上的能量、频谱与发展证据。它可以显示动作空隙中的音乐仍延续，也能帮助比较簇与乐句的尺度。每帧使用 40 ms 支撑，10 ms hop 不是 10 ms 起音精度。音频和动作边界没有逐事件一一对应的保证；不能仅从频谱推断 mapper intent 或独立手指需求。

## 积累与验证

每轮以当前 canonical 记录核对清单，逐例保留确切人类 ID、实际读过的源码范围、关键 witness、三个视角的解释以及反例。保存少量跨例关系经验，检索时重新打开来源；不把 139 条学习笔记变成 139 条新的机器训练标签。

检查分三个层次：源码与引用是否正确；解释是否容纳已知正负和强弱对照；换一个真实组织后是否仍适用。覆盖清单证明第一轮没有漏例，不能证明心理上的“学透”。未解区应写出还不能区分的具体关系，避免只写“需要更多数据”。

研究连接是为 [gameplay frontier](../../Pulsefield-model/docs/formulation/gameplay-state.md) 提供候选问题：在相同下一动作前，既有保持、交替历史、相邻复打或无攻击间隔分别留下什么区别？空隙是否仍被 LN 占用？一个列的腾空是否发生在其余列持续保持的背景中？这些问题有自然实例支持，但还没有响应尺度或答案标签。整段读谱可以利用后文解释组织；生成时的历史表示只能使用已提交前缀，不能把实际未来偷偷放入状态。
